# Cleanup plan

This is a checklist of cleanup work from a full code review made on 2026-11-17 at commit `9f6cae1`.
Each item is written so that an engineer or a coding agent can do it without reading the review.
Work through one item at a time, and tick it when its verification passes.

## How the review was made

Eleven reviewers each read one area of the code in full, and one reviewed the architecture across areas.
The review was stopped early to limit cost.
Ten of the eleven reviewers had read every file in their area before the stop.
"Not read" at the end of this file lists what the others left out.
Line numbers refer to commit `9f6cae1` and move as the code changes, so each item also names the function or type.
Line savings are estimates from line counts, not from trial changes.
An item marked SUSPECTED was inferred and must be confirmed before work starts.

Measured at the time of the review: 124,500 lines of production Rust and 71,000 lines of tests.
Copy-paste is about 1.2% of production code, so the size does not come from repetition.
It comes from large files, state that is stored twice, per-feature plumbing, and code kept only for tests.

## Rules for every item

1. Read `AGENTS.md` first and follow it: stage explicit paths, no co-author trailers, no force-push, commit locally and do not push unless the owner asks.
2. One item per commit. The commit message says why, in plain sentences.
3. Do not change behavior unless the item says so. If you find a defect while doing a mechanical item, write it under "Defects found" at the end of this file and leave it alone.
4. Do not touch release, packaging or updater code (`scripts/`, `sparkle`, `updates.rs`) unless an item names it.
5. Do not delete anything listed under "Kept on purpose".
6. Prose in comments and docs: one sentence per source line, no em dashes, plain technical wording.
7. A worktree may start from an older commit than local `main`. Run `git merge --ff-only main` before you start, and say in your report which commit you started from.
8. Cargo keeps every old build. Check `du -sh target` now and then, and run `cargo clean` when it passes 100 GB.
