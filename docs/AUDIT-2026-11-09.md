## 2. Data loss and crashes

- RESOLVED (foreign glyph preservation): Glyphs and Fontra importers record original glyph import status separately from the current glyph set.
  Write-back preserves unsupported glyphs without resurrecting intentionally deleted imported glyphs, including across repeated saves.
  Older working copies without provenance fail with a reopen instruction instead of guessing which absent glyphs to delete.
- RESOLVED (Fontra component preservation): component locations and extension fields travel in identity-bound object metadata instead of being reconstructed from only the base and transform.
- RESOLVED (Save As isolation): successful publication clears foreign write-back ownership; failed publication preserves the original binding and document state.
- RESOLVED (smart-component mutation invariants): decomposition and composition proposals clear values for discarded components; proposal installation prunes removed identities while retaining surviving foreground values.
  Regressions reproduced the original `MissingComponent` projection panics and stale-value retention before the fixes.
  Coverage includes projection, layer copying, component reordering, save/reopen, undo/redo, and no-op decomposition without weakening projection assertions.
- RESOLVED (canonical import panic): `Project::from_source` returns `Result<Project, ProjectImportError>` and preserves typed validation causes.
  Regression coverage sends malformed `public.skipExportGlyphs` through the decoded-source, disk UFO/designspace, and memory-folder import boundaries.
- RESOLVED (glyph lifecycle references): guarded rename/remove transactions update `public.glyphOrder`, `public.postscriptNames`, both sides of Designspace substitutions, and supported HOI trajectory glyph references.
  Font-lib changes invalidate source metadata, and changed Designspace data is marked dirty so ordinary Save persists it.
  Rename retains production-name values; removal retains empty rule identities and conditions.
  Unsupported HOI, malformed reference metadata, and occupied destination entries reject instead of silently losing data.
  Regressions cover model preservation, multi-source save/reopen, stale and malformed transaction rejection, and existing layer undo/redo after rename.
  This does not add whole-glyph lifecycle undo or rewrite feature-program text.
- CONFIRMED LIMITATION (compiler categories): `unassigned` and `component` are valid [UFO categories](https://unifiedfontobject.org/versions/ufo3/lib.plist/#publicopentypecategories), not malformed metadata.
  The [pinned Babelfont IR adapter](https://github.com/simoncozens/babelfont-rs/blob/29bdedbbfa7d3150b651dbd7c94fce6b79677ca4/babelfont/src/convertors/fontir/static_metadata.rs#L19-L39) maps every category other than base, mark, and ligature to base.
  Runebender therefore rejects these explicit categories during compilation rather than silently misclassifying them; importing, editing, and saving retain them.
  Supporting them requires preserving GDEF classes zero and four through the compiler adapter and verifying emitted GDEF tables, not treating either as base or inferred.
  Category inference now scans anchors without collecting them; precedence coverage keeps explicit classes authoritative and mark evidence ahead of ligature evidence.
- `src/application/platform/host.rs:688-745`: a reload resets most presentation state, starts a new live server, keeps a stale session outside editor mode, and leaves `features_buf` on master 0.

## 12. Comparison with Fontra, Shift and Counterpunch

Sources: `github.com/fontra/fontra`, `github.com/shift-editor/shift`, `github.com/counterpunchspace/editor`.

Runebender has these and the others do not:

- One native Rust widget tree that also compiles to the browser.
- Local model features with no account, and agent edits with proposals, receipts and explicit authorization. The MCP server of Shift is read-only.
- Byte-exact GLIF preservation with a test.
- Tests that enforce architecture and interface rules.
- Higher-order interpolation authoring, hyperbezier pen, metaballs, image tracing, and measured analysis.
- A permissive license together with UFO write support.

The others have these and Runebender does not:

- RESOLVED comparison: Runebender now also runs Playwright tests in CI on each pull request.
- Automated releases for macOS, Windows and Linux, and a nightly channel (Shift, Fontra Pak).
- `cargo deny` for licenses and sources, `cargo machete`, crate-boundary checks and performance-budget tests (Shift).
- Windows as a tested platform (Fontra, Shift).
- Interface localization (Fontra).
- Sparse sources, glyph-level axes, avar-2 and variable components (Fontra).
- Collaboration (Fontra, Counterpunch) and crash recovery for unsaved edits (Shift).
- A plugin API (Fontra, Counterpunch).
- README tables for feature status and format support, a public roadmap, and an issue template (Counterpunch, Shift).

Practices to adopt, in order of value:

1. DONE: run the existing browser checks in CI; see the resolved finding in section 1.
2. Move packaging into a release workflow and add Linux and Windows artifacts.
3. Extend `deny.toml` to licenses and sources, and add `cargo machete`.
4. Move the font engine into its own crate, so the `application` feature becomes a crate boundary.
5. Add feature and format tables to the README.
6. Read sparse sources and glyph-level sources.
7. Add performance-budget tests for open, interpolate and compile.
8. Add an edit journal for crash recovery.
9. Add an issue template; the short [contributor guide](CONTRIBUTING.md) is now available.
10. Move interface strings into a keyed table.
