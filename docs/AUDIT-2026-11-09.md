# Audit findings for review, 2026-11-09

This file lists the audit findings that were not changed in the working tree.
Each item came from a read of the code by a reviewer.
The items were not all verified a second time, and one reported item was wrong when checked (`GraphRunRequest::validate_source` has a production caller).
Check each item against the code before you act on it.
Items marked UNVERIFIED depend on runtime behavior that no one ran.

## 1. CI state

- macOS CI fails on `main`: five graph tests time out on the runner and pass locally.
  The tests are `cancelling_a_dag_releases_earlier_proofs_while_script_cancellation_settles`, `generated_node_geometry_applies_the_exact_preview_and_replays_its_ids`, `node_commands_share_images_retry_receipts_apply_and_ordinary_undo`, `the_specimen_renders_on_open_and_again_after_edits_settle` (`src/application/editor/tools/graph/workspace.rs`) and `paired_proofs_retain_exact_images_and_release_without_recompiling` (`src/application/platform/graph_proofs.rs:261`).
  Each waits on a wall-clock deadline for a proof render.
- CI installs a pinned `designbot` before `cargo test`, and no document lists this prerequisite.
- CI does not build the browser editor and does not run the Playwright checks in `web/*.cjs`.
  `docs/HOI-RESEARCH-PLAN.md` records `web/quality.cjs:115` as a failure on three runs.
- `cargo deny` does not check `web/Cargo.lock`, and no schedule runs the advisory job.
- Actions use mutable tags, and no workflow has a `permissions:` block.
- `web/prepare.py` rewrites two tracked manifests as a build side effect and lists upstream dependencies by hand.

## 8. Performance

- `GlyphList::get` is a linear scan, so `dependent_component_layers` is quadratic and runs on each committed edit (`src/font/variable.rs:467`).
- Each source or layer operation takes two or more whole-font snapshots and keeps both in a 128-step history (`src/font/sources.rs:154`).
  Proposal install pays this cost once for each glyph.
- `encode_source` clones and rebuilds the font lib once for each glyph (`src/font/persistence/ufo_codec.rs:112`).
- HOI records are parsed and bound on each interpolation call (`src/font/hoi.rs:298`).
- `Project::save` encodes, stages and reloads each source, clean or not.
- `sync_session_from` clones the session on each editor event (`src/application/editor/session.rs:2590`).
- Six pump tasks post a message on each tick, so the view tree rebuilds up to 25 times a second while idle (`src/application/view/render.rs:499`).
- `text_label::draw` shapes a new layout on each call from 27 paint sites, and `menu_shell::title_rect` shapes about 45 titles for each pointer event.
- The canvas lays out the text line at least seven times for each paint (`view/canvas/editor.rs:1316`).
- The sidebar walks the whole font for each category on each rebuild (`view/panels/tabs.rs:625`).
- `source_fingerprint` hashes every source file on the UI thread, twice for each save (`platform/host.rs:44`).
- `model_strip.rs:462` requests an animation frame without a condition.
- The disk MCP tools load the project up to three times for each call (`cli/agent_commands.rs:10`).
- A graph run hashes model directories once for each port (`workflows/graph_run.rs:128`).

## 12. Comparison with Fontra, Shift and Counterpunch

Sources: `github.com/fontra/fontra`, `github.com/shift-editor/shift`, `github.com/counterpunchspace/editor`.

Runebender has these and the others do not:

- One native Rust widget tree that also compiles to the browser.
- Local model features with no account, and agent edits with proposals, receipts and explicit authorization. The MCP server of Shift is read-only.
- Byte-exact GLIF preservation with a test.
- Tests that enforce architecture and interface rules.
- Higher-order interpolation authoring, hyperbezier pen, metaballs, image tracing, and measured analysis.
- A permissive license together with UFO write support.

The others have these and Runebender does not:

- Playwright tests in CI on each pull request (Shift, Counterpunch).
- Automated releases for macOS, Windows and Linux, and a nightly channel (Shift, Fontra Pak).
- `cargo deny` for licenses and sources, `cargo machete`, crate-boundary checks and performance-budget tests (Shift).
- Windows as a tested platform (Fontra, Shift).
- Interface localization (Fontra).
- Sparse sources, glyph-level axes, avar-2 and variable components (Fontra).
- Collaboration (Fontra, Counterpunch) and crash recovery for unsaved edits (Shift).
- A plugin API (Fontra, Counterpunch).
- README tables for feature status and format support, a public roadmap, and an issue template (Counterpunch, Shift).

Practices to adopt, in order of value:

1. Run the existing `web/*.cjs` checks in CI.
2. Move packaging into a release workflow and add Linux and Windows artifacts.
3. Extend `deny.toml` to licenses and sources, and add `cargo machete`.
4. Move the font engine into its own crate, so the `application` feature becomes a crate boundary.
5. Add feature and format tables to the README.
6. Read sparse sources and glyph-level sources.
7. Add performance-budget tests for open, interpolate and compile.
8. Add an edit journal for crash recovery.
9. Add an issue template and a short `CONTRIBUTING.md`.
10. Move interface strings into a keyed table.
